# 記事スタイルガイド

Zenn 記事（`articles/*.md`）を書くときの基準です。Claude が下書きするときは、書く前にこのファイルを読み、書いた後に NG 表現と照合します。

根拠は公開記事 32 本の棚卸し（[`style-audit-2026-10.md`](style-audit-2026-10.md)）です。型は、構成と文体が最も揃っている OpenClaw 連載 #1〜#7（2026-05）から取っています。

## 1. テーマ選び

- **テーマが決まっていないときは how-to（手順・構築・トラブル解決）を推奨案として出す**
  - 根拠: いいね数の上位は how-to 型（Obsidian 自動同期 29、OpenClaw #1 7）。評論・振り返り型は 0〜1
- 体験記にする場合も、読者が手元で再現できる手順や数値を必ず入れる

## 2. 文体

| 項目 | 基準 | 実例（OpenClaw 連載より） |
|---|---|---|
| 基本 | です・ます（文末の 9 割前後） | 「結局 **rsync 法** が現実解でした」 |
| 列挙の前置き | 「〜は以下です」で箇条書きにつなぐ | 「理由は主に以下です」「今回使った主なパーツは以下です」 |
| 過去の作業 | 「〜でした」「〜しました」で書く | 「実際にハマった瞬間がこれでした」 |
| 推測・未確認 | 断定せず「〜ようです」 | 「温度が低いと回らないことがあるようです」 |
| 一人称 | 多用しない。必要なときは「自分」 | 「自分のマシンに自分で SSH するときも…」 |
| 失敗 | 隠さず書く。「ハマった」「結局〜にした」 | 「forward 経路は結局開通せずに、#7 で Win 集約に転換することになります」 |
| 感情 | 短く素直に書いてよい | 「自己署名証明書を毎回承認するのが鬱陶しい」 |

- だ・である（常体）にしない。Claude の下書きが常体の硬い技術文書調になり、4 記事を全面的に書き直した経緯があります（#2）
- 1 文を短くして、改行を多めにする

## 3. タイトル

- 連載: `OpenClaw自動化サーバー構築記 #N サブタイトル`（CLAUDE.md の規約）
- 単発: 「何をしたか / 何が起きたか」が分かる 1 文。疑問形は可
- タイトルに `#` や絵文字を入れない（絵文字は frontmatter の `emoji` に入れる）

## 4. 構成テンプレート

```markdown
## TL;DR
（3〜5 行の箇条書き。要点だけ太字）

## はじめに
（何をしたかったか・なぜ書くか）

## なぜ X を選んだか / 全体像
（比較表・構成図。不要なら省略）

## Step 0: 〜
## Step 1: 〜
### （Step 内の小見出し）

## ハマりどころ
（症状 → 原因 → 対処。連載では「ハマりポイントまとめ」）

## まとめ

## 次回予告
（連載のみ）

## 参考リンク
```

- 手順の節は `Step N:`（0 始まり可）で統一する。`1.` `第1章` `①` `Section 1` は使わない
- 見出しは h2（`##`）から始める。本文で h1（`#`）を使わない。h3 を h2 の代わりにしない
- 見出しに絵文字を入れない

## 5. 記法

| 要素 | 使い方 |
|---|---|
| `:::message` | 後日談・注意・前提の訂正。本文の流れから外れる補足に使う |
| 太字 | TL;DR と結論の 1 文に絞る。段落ごとに入れない |
| コードブロック | 実行したコマンドと出力。PII は CLAUDE.md の規約でマスクする |
| 表 | 案の比較・構成部品・Before/After |
| 図 | フローは mermaid、数値は `scripts/figures/`（`/zenn-article` Phase 4） |
| 数値 | 段落の直後に `出典: …（Sxx）`（`/zenn-article` 共通ルール） |

## 6. 締め

- 順序は「まとめ → 次回予告（連載のみ）→ 参考リンク」
- 箇条書きのまま終わらせない。まとめの 1〜3 文で結論を言い切る
- 連載は前回・次回の記事へリンクする

## 7. NG 表現

| NG | 言い換え | 理由 | 出典 |
|---|---|---|---|
| 成立させる / を成立する | できた / 動いた | 編集者目線で客観的すぎる | #2 |
| 採った | 選んだ | 書き言葉 | #2 |
| 事実関係が | 起きたことは | 書き言葉 | #2 |
| 記事の山場 | 一番ハマったところ | 編集者目線 | #2 |
| 初心者向け / ジュニアエンジニア向け / 初心者が挑む | 書かない | 読者を見下ろすラベル | memory, commit 24b1f46 |
| だ・である の文末 | です・ます | 著者の文体と別人になる | #2 |
| タイトル先頭の `# ` | 外す | Markdown 記号の混入 | 棚卸し |
| 本文の h1 / 見出しの絵文字 | h2 から・絵文字なし | 見出しレベルと装飾の不統一 | 棚卸し |
| `<!-- 会長: -->` の空欄 | ヒアリングして Claude が書く | 会長への丸投げ | `/zenn-article` |
| 「記事メタ情報」など執筆メモ | 公開前に消す | 下書き用の情報が本文に残る | 棚卸し |

NG 表現を新しく見つけたら、この表と frontmatter の `ng_phrases` / `ng_patterns` の両方に追加します。
